01 / GET STARTED

Download.
Build.
Evolve.

Use the complete source archive. The public headers link to a compiled library, with the implementation included under src/.

The default run is a small functionality example. Set physical and numerical parameters for your study.

1

Get the source

Download .tar.gz or .zip. Both contain the same source.

tar -xzf bose-polaron-gpe-0.2.0.tar.gz
cd bose-polaron-gpe-0.2.0
2

Prepare a project environment

Conda installs the declared dependencies into a dedicated environment. Existing compatible dependencies can also be used.

conda env create -f environment.yml
conda activate bose-polaron-gpe
3

Build, test, and run

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
./build/gpe --output results

Requires a C++17 compiler, Eigen 3.3+, zlib, libarchive with gzip/XZ support, CMake 3.17+, and Python for tests. Each run needs a new output directory.

02 / THE C++ LIBRARY

One solver.
Two starting points.

Set gpe::SimulationParameters and link your program to gpe::solver. The complete example runs a fresh simulation, then resumes directly from its compressed archive.

FRESH RUN / STATE IN MEMORY

GPE_solver

Begin from a uniform field or a supplied Eigen complex vector. Save velocity records and compressed configurations as the field evolves.

#include <gpe/solver.hpp>

// Inside your simulation program:
gpe::SimulationParameters parameters;
parameters.output_directory = "my-simulation";
auto result = gpe::GPE_solver(parameters);
RESTART / COMPRESSED FILE ON DISK

GPE_solver_contd

Continue at a positive checkpoint time. Supply its recorded velocity, retain the original injection velocity V₀, and select the saved field.

#include <gpe/GPE_solver_contd.hpp>

// Retain the original physical/grid settings.
parameters.t_initial = checkpoint_time;
parameters.t_final = next_final_time;
parameters.initial_velocity = checkpoint_velocity;
parameters.output_directory = "continued-results";
auto result = gpe::GPE_solver_contd(
    parameters, checkpoint_file, "phi_20.dat");

Stream the checkpoint. Read a single .dat.gz / .dat.xz field, or select a member inside a gzip/XZ tar archive. A 64 KiB text buffer feeds the field vector without writing an expanded checkpoint. Decoder buffers and numerical working vectors still use memory.

For file continuation, leave initial_field empty. The checkpoint time, velocity, and matching physical parameters are supplied by the caller. For a single compressed field, omit the member-name argument.
